A disclosure accordion built around a single visual hook: when an item opens, the answer text doesn't fade in — it gets *wiped* into focus by a shimmer gradient that travels line-by-line. Each answer's wipe duration is tied to its character count, so longer answers sweep proportionally longer (driven by a `cps` — characters-per-second — prop).

The trick is `display: inline` on the answer paragraph, which makes the gradient repeat per text-line fragment, plus `background-clip: text` so the moving band paints the glyphs themselves. Reduced-motion users skip the wipe and see the resting muted text directly.


## Mechanism

The shimmer is **three** `background-image` layers stacked on the answer `<p>`, all `background-clip: text`. The text itself is `color: transparent` so the gradients paint the glyphs directly.

1. **Wipe band.** A `linear-gradient` containing one bright color band at the right edge of a 200%-wide layer. `background-position` animates from `200% 0` (band off-screen right) to `0 0` (band off-screen left) — the band sweeps across each line, then exits.
2. **Midtone fill.** A solid mid-tone color covering the full 200%-wide layer. Slides in alongside the band, so after the wipe completes the text settles into a readable mid-tone (not back to invisible).
3. **Rest tone.** A flat near-invisible layer always at `0 0`. Before the wipe arrives, only this layer paints the text — that's what makes the wipe read as a **reveal** rather than a highlight passing over already-visible text.

The paragraph uses `display: inline`, so each text-line fragment gets its own copy of the gradient. That's the per-line wipe.

Wipe timing scales with content length:

```css
transition-duration: calc(var(--char-count, 200) / var(--cps, 50) * 1s);
```

`--char-count` is set per item in the frontmatter (Astro reads `answer.trim().length`). `--cps` is set on the wrapper from the `cps` prop.

## Theming

Every color resolves through semantic tokens — drop the component inside `[data-theme="dark"]` and it inverts automatically. The shimmer color is `--color-fg`, the resting color is `--color-fg-subtle`. Override via CSS vars on the wrapper:

| Variable               | Default                                                    | Purpose                                        |
|------------------------|------------------------------------------------------------|------------------------------------------------|
| `--shimmer-color`      | `var(--color-fg)`                                          | Bright band that flashes across as the panel opens. |
| `--shimmer-mid`        | `color-mix(in srgb, var(--color-fg) 65%, transparent)`     | Tone the text settles into after the wipe completes. |
| `--shimmer-rest`       | `color-mix(in srgb, var(--color-fg) 12%, transparent)`     | Pre-wipe baseline — near-invisible so the wipe reads as a reveal. |
| `--shimmer-spread`     | `20`                                                       | Band width in `ch` (mirrors the `shimmerSpread` prop). |
| `--shimmer-ease`       | `var(--cubic-default)`                                     | Easing for the wipe.                           |
| `--shimmer-speed`      | `var(--timing-default-quarter)`                            | Duration for non-shimmer transitions (panel height, plus icon, etc.). |

Example — green shimmer over default text:

```astro
<AccordionShimmer
  class="my-faq"
  items={[/* … */]}
/>

<style>
  .my-faq { --shimmer-color: var(--color-success); }
</style>
```

## Accessibility

- Triggers are native `<button>` with `aria-expanded` + `aria-controls` wired to each panel.
- Panels carry `role="region"` and `aria-labelledby` pointing at the trigger button.
- Single-open mode mirrors common FAQ behavior; opt out with `closePrevious={false}` for multi-open.
- `aria-hidden="true"` on decorative icons (the question text already names the row).
- The shimmer wipe is wrapped in `@media (prefers-reduced-motion: no-preference)` — reduced-motion users see the resting muted text immediately on open with no wipe.
- Selection styling (`::selection`) uses the shimmer color so highlighted text stays legible (without it, transparent glyphs would vanish on selection).

## Notes

- The `--char-count` per item is computed at render time from `answer.trim().length`. If you stream answers from Markdown or rich content later, recompute this with text-only length, not raw HTML length.
- `display: inline` on the answer means it can't carry block layout (margins, padding) directly. Block spacing lives on the parent `.accshim__panel-inner` instead.
- Wider `shimmerSpread` values look better for shorter answers; very short answers (< 30 chars) with a 20 ch spread can wipe almost instantly.
- Single shimmer band only — the original effect supports multiple stacked color bands for chromatic effects. Add a second `linear-gradient` to the wipe layer if you want neon-duo behavior.
